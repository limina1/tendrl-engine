* VERDICT (critical question)

*Currently unwired by the web (HIGH confidence) — but the pure algorithmic core is the
intended source of truth, not dead weight. See [[file:08-frontend-backend-boundary.org][08]] for the keep/drop split.*

The module is documented as an "interface-agnostic tree navigation" engine meant to
serve both a ratatui TUI and the web UI through an async boundary. Reality:

- *The TUI no longer exists.* =Cargo.toml= declares exactly one =[[bin]]=
  (=nostr-engine= → [[src:src/main.rs][src/main.rs]]); there is no =src/bin/=, and *no
  =ratatui=/=crossterm=/=tui= dependency anywhere* (=rg -i "ratatui|crossterm|tui"
  Cargo.toml= → NONE). The consumer the engine was built for is gone.
- *The navigation engine has zero production consumers.* Outside =src/tree/= itself:
  =TreeEngine= 0 refs, =TreeCommand= 0, =TreeState= 0, =AsyncRequest=/=AsyncResult=/
  =CommandResult= 0, =apply_async_result= only its own def + docstring
  ([[src:src/tree/engine.rs::303][engine.rs:303]]). The "key architectural pattern" (the async boundary) is
  exercised *only by the module's own 58 unit tests*.
- *What IS live is a narrow set of compose/serialization structs from [[src:src/tree/state.rs][state.rs]]*,
  used by api.rs/engine.rs/publication.rs/drafts.rs/tree_emit.rs: =ComposeState= (67
  ext refs), =SectionCompose= (24), =TagEntry= (16), =ComposeBlockState= (13),
  =BlockKind= (10), =ComposeBlock= (4). These are passive payload containers — not
  tree navigation.
- *The web reimplements tree + compose logic in TypeScript.*
  [[src:web/src/lib/wm/renderers/ReaderBuffer.svelte][ReaderBuffer.svelte]] assembles its own addr-keyed tree from SSE and does its own
  outline collapse/depth handling; =web/src/lib/compose/state.ts= is a parallel compose
  state machine. There are *no =/tree/= HTTP routes* — the web never calls the Rust
  tree engine. The publication tree it consumes comes from the depth-N loader in
  =publication.rs=/=tree_emit.rs=, not =tree::engine=.

The compiler doesn't flag this because the crate is a library and the types are
=pub=/re-exported — Rust suppresses dead-code warnings for public API.

* Prioritized findings

** [HIGH] The entire navigation engine is dead weight
   - where :: =src/tree/{engine.rs(1585),command.rs(1172),render.rs(307),node.rs(401),undo.rs(254),content.rs(216)}= + the navigation half of =state.rs=
   - what :: =TreeEngine=, all =TreeCommand= variants, =CommandResult=, =AsyncRequest=/
     =AsyncResult=, =TreeRenderer=/=VisibleNode=/=RenderOptions=, =TreeNode=/=NodeId=/
     =ContentMode=, =ContentDetector=, =UndoStack=/=Operation=, and TUI state types in
     state.rs (=TreeState=, =ViewMode=, =FilterMode=, =ComposeFocus=, =WindowManager=,
     =CommandPaletteState=, =LoginDialogState=, …) all have *0 external references*
     (verified per-type with =rg=).
   - action :: Delete the navigation/TUI surface. Conservative path: extract the 6 live
     compose structs into =publication/compose.rs= (or =src/compose_types.rs=), repoint
     the ~140 external refs, then drop =command.rs=/=engine.rs=/=render.rs=/=node.rs=/
     =undo.rs=/=content.rs= and the dead two-thirds of =state.rs=. Removes ~5,000+ loc.

** [HIGH] state.rs is a 3061-loc god-object mixing live and dead concerns
   - where :: [[src:src/tree/state.rs][state.rs]]
   - what :: 25+ structs/enums spanning publish-payload data (live: =ComposeState= etc.,
     ~547–1480) AND TUI window management / dialogs / clipboard / view modes (dead:
     =TreeState= @40, =WindowManager= @2090, =LoginDialogState= @2339, …).
   - action :: Covered above — the live structs are a clean separable cluster.

** [MEDIUM] undo.rs is an admitted stub reachable only through dead code
   - where :: [[src:src/tree/undo.rs::4][undo.rs:4]] ("stub implementation to be expanded in Phase 4")
   - what :: =UndoStack= referenced only via =TreeState.undo_stack= ([[src:src/tree/state.rs::60][state.rs:60]]),
     which is never instantiated outside the module. The web-pivot bypassed Phase 4.
   - action :: Delete with the navigation engine.

** [MEDIUM] parser.rs (690 loc) is unused — parsing is done by the Python sidecar
   - where :: [[src:src/tree/parser.rs][parser.rs]]; [[src:src/api.rs::1028][api.rs:1028]] =parse_document_handler=
   - what :: =ParsedDocument=/=ParsedLine=/=ParsedSection=/=LineType= have 0 external
     refs; the only =/api/v1/documents/parse= route forwards bytes to the *sidecar
     =/parse=* and returns its JSON verbatim — never touches =tree::parser=.
   - action :: Delete unless you intend to move parsing in-process (a new decision).

** [LOW] mod.rs docstring + re-exports advertise an API nobody consumes
   - where :: [[src:src/tree/mod.rs::1][mod.rs:1]]
   - what :: The module doc sells the =TreeEngine=/=CommandResult::NeedsAsync= pattern
     as "the key architectural pattern" and re-exports ~24 types of which only 6 are
     used. Matches the stale =CLAUDE.md= claim that the TUI "remains functional".
   - action :: After the cull, rewrite mod.rs to describe what remains (compose payload
     types); update the =CLAUDE.md= =src/tree/= section to stop claiming a live TUI.

* Supporting evidence
- One binary, no TUI: =Cargo.toml:16-18=, no =src/bin/=, no ratatui/crossterm.
- Navigation types 0-ref externally (per-type =rg=): VisibleNode, TreeNode, NodeId,
  TreeRenderer, RenderOptions, ContentMode, ContentDetector, AppMode, ViewMode,
  FilterMode, ClipboardContent, CommandPaletteState, EditorComposeState, ParsedDocument,
  LineType, UndoStack, Operation, WindowManager, WindowState, LoginDialogState,
  UserDataMenuState — all 0.
- Live types: ComposeState 67, SectionCompose 24, TagEntry 16, ComposeBlockState 13,
  BlockKind 10, ComposeBlock 4.
- No =/tree/= HTTP routes; web builds its tree in ReaderBuffer.svelte:863 and compose
  logic in web/src/lib/compose/state.ts. =parse_document_handler= → sidecar =/parse=.

Net: roughly *5,000–6,000* of the module's ~7,700 loc is removable dead code; the
residual ~1,000 loc of compose payload structs should be relocated out of a module
whose name and doc no longer describe its contents.
