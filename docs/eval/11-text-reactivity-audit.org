#+TITLE: Text Reactivity Audit — Why Text Spills on Zoom and Length
#+DATE: 2026-06-14
#+STATUS: Audit only — no edits applied

* Symptom

"Our text isn't reactive — things spill everywhere depending on zoom and
text length." Two *independent* failure modes are conflated under one
symptom. They have different root causes and different fixes.

* Root cause, in one paragraph

The design token system (=web/src/lib/styles/tokens.css=) is defined
entirely in =px= — the type scale, spacing, chrome heights, and radii are
all absolute. =:root= has *no =font-size= anchor*; the only font-size is on
=html= (line 107) and it too is a px token. Meanwhile the component layer
overwhelmingly sets =font-size= in *bare =rem=* (e.g. =0.75rem=,
=0.9rem=), bypassing the token scale entirely. So the app has two scaling
axes that move independently:

- *px chrome* (panels, headers, row heights, gaps, token-driven text) —
  fixed under OS font-scaling and browser text-only zoom.
- *rem component text* — grows under those same controls.

When the rem text grows but the px box around it does not, the text
overflows. That is BUG 1. Separately, long unbroken strings (npubs, 64-hex
ids, URLs) and under-guarded flex chains overflow regardless of zoom — that
is BUG 2.

* The two bug classes

** BUG 1 — Unit incoherence (the "depends on zoom" axis)
The px token scale and the rem component font-sizes scale on different axes.
Nothing scales as a *unit*. Sub-cases:
- =rem=/=em= font-sizes in components (the dominant case — present in the
  large majority of components).
- Hardcoded =px= font-sizes that should reference =--t-*= tokens.
- =calc(var(--t-xs) - 1px)= — token mixed with a px nudge, re-introducing
  absolute drift.

** BUG 2 — Overflow not contained (the "depends on text length" axis)
- *2a — flex =min-width:0=*: a flex child only clips/ellipses/wraps if it
  *and every flexible ancestor* carry =min-width:0=. Missing it anywhere in
  the chain makes the child report content width as its min size and shove
  siblings out.
- *2b — long tokens*: npub / 64-hex / URL / long title rendered without
  =overflow-wrap=/=word-break=/=text-overflow:ellipsis=.
- *2c — fixed dimensions*: hard =width:NNNpx= / =height:NNNpx= (not
  =max-/min-=) on text containers that cannot shrink.

* Headline numbers
- ~2,100 raw =px= literals across components; ~48 =min-width:0= sites;
  ~77 overflow guards total.
- BUG 1 is *systemic*, not local: the component layer is rem-first while
  the token system is px-first. This is the dominant cause of the
  zoom-dependent spill.
- BUG 2 is *localized*: a handful of real flex-chain and long-token gaps,
  listed above. The codebase already guards most ids/titles with
  =text-overflow:ellipsis= + =min-width:0= — the gaps are the exceptions.

* Prescription (for when edits are authorized)

** Fix A — establish one scaling model (resolves BUG 1)
1. Anchor the root: =:root { font-size: 13px; }= (the single knob; now
   honors OS font-scaling and browser text-only zoom).
2. Convert the type scale to rem in tokens.css:
   | token     |  px | rem      |
   |-----------+-----+----------|
   | --t-xs    |  11 | 0.846rem |
   | --t-sm    |  12 | 0.923rem |
   | --t-base  |  13 | 1rem     |
   | --t-md    |  14 | 1.077rem |
   | --t-lg    |  16 | 1.231rem |
   | --t-xl    |  19 | 1.462rem |
   | --t-2xl   |  24 | 1.846rem |
   | --t-3xl   |  32 | 2.462rem |
   (Spacing --s-* and chrome --header-h/--statusbar-h/--panel-header-h/
   --rail-w should follow to rem too, so chrome scales with text. Radii may
   stay px.)
3. Replace bare =rem= / hardcoded =px= font-sizes in components with =--t-*=
   tokens (the long per-file list above). Add the missing =--t-2xs= token
   (≈10px → 0.77rem) rather than leaving =0.7rem= fallbacks and =9px=/=10px=
   literals. Kill the =calc(var(--t-xs) - 1px)= pattern — make a token instead.

After A, a single root knob (or the browser's own text zoom) scales the
*entire* UI together — no more rem-text-in-px-box mismatch.

** Fix B — contain overflow (resolves BUG 2)
1. Global defensive rules (app.css):
   #+begin_src css
   .panel, .panel-body, .row__body, .scard__body { min-width: 0; }
   .mono, .codebox, .modal__field { overflow-wrap: anywhere; }
   #+end_src
2. Add =min-width:0= to the flagged flex chains: FeedBuffer .row-head,
   DiscussionViewBuffer .dv-ref-value, IgnoredBuffer .ignored-id,
   PublishProgressBuffer .pp-event-title, DocBuffer .author-name,
   ProfileView .item-title, SearchResultItem .result-title/.result-header-text,
   +page.svelte .hs-popover__list / .mb__list.
3. Add =overflow-wrap:anywhere= (or =word-break:break-all=) to long-token
   sinks lacking it: ChatMessage/ClaudeSessionView <pre> JSON,
   DiscussionViewBuffer .dv-ref-value, IgnoredBuffer .ignored-id.
4. Convert hard widths to shrinkable: tokens.css =.modal=
   =width:min(560px,92vw)=, =.picker= =min(360px,92vw)=; +page.svelte
   =.win--left/right= keep flex-shrink but add a =min-width= floor or move to
   =clamp()=; component fixed inputs (EmbeddingSettings 150px, SearchConfig
   150/140/72px, ComposeView 200px) → max-width.

* Recommended order
1. *Fix A first* — highest leverage, lowest risk, and it is the change that
   actually matches "make text reactive to zoom." Do tokens.css + the global
   anchor, then sweep components to tokens.
2. *Fix B second* — mechanical, localized, low blast radius. The flagged
   sites are few and explicit.

Both are independent; A does not depend on B. Neither requires touching
Rust — this is entirely the =web/= layer.
