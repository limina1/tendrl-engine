* 1. RefsBuffer / reference pool — VERDICT: pool BUILT, standalone RefsBuffer intentionally RETIRED (not a gap)

The reference pool is *fully implemented* in [[web:src/lib/state.svelte.ts][state.svelte.ts]]: the three-membership
model (=in_context= / =in_compose= / =held=) is real — =addToPool= (line 544), =gc()=
keeping any held item (592), =heldEntries= derived view (599), =togglePoolMembership=
with a ='held'= path (697), =holdEvent= (734). The routes off the pool (→compose /
→chat / →search / drop) exist.

The standalone =RefsBuffer.svelte= ("currently a stub" in workbench-arch:878) was
*deliberately folded* into [[web:src/lib/components/SearchPanel.svelte][SearchPanel.svelte]]'s "Refs" tab (research-class single buffer
cycles Search · Refs · Import via =h=/=l=). Documented as shipped (=workbench-arch:1650=
=[x] standalone RefsBuffer retired=; restated in =registry.ts:48-52= and
=+page.svelte:50-51=). So the doc's RefsBuffer section is *stale narrative*, not an
unbuilt item. Citations (NKBIP-03 mint) remain the genuinely-unbuilt downstream piece.

* 2. Redundant renderers — NOT duplicates; each has a distinct role
- =ReaderBuffer.svelte= (99KB) — the publication tree reader (depth-N TOC, pager/
  outline/continuous, focus stack, discussions, highlights). Opened for =kind:'reader'=.
- =DocBuffer.svelte= — slim single-event viewer for 30023/30818 (parses
  =doc:<kind>:<pk>:<dtag>= at =:34=); drops the pager. Reachable from =ProfileBuffer:35=.
- =DraftReader.svelte= — compose-section reader (outline/continuous/paginated of
  =ComposeState.sections= with lock/fork state). Used inline by =ComposeView:900=.
- =DraftReaderBuffer.svelte= — a 36-line thin wrapper adapting =DraftReader= into the
  registry (=kind:'draft-reader'=).

Verdict: no true duplication. =DraftReaderBuffer= is a legitimate adapter. Reader-vs-Doc
overlap is defensible (different event shapes).

* Prioritized findings

** [high] M-x palette has ~13 declared commands with no dispatch
   - where :: [[web:src/routes/+page.svelte::158][+page.svelte:158-194]] declares 28 commands; =executeCommand= (:314-408)
     handles 14 with a silent =closeMinibuffer()= fallthrough at *:406-407*.
   - what :: Non-functional via M-x: =tendrl-kill-buffer=, =find-event=, =find-draft=,
     =split-window=, =switch-layout=, =save-layout=, =save-draft=, =publish-draft=,
     =fork-section=, =cycle-editor-view=, =undo=, =redo=, =quit=, =refresh=. Several are
     reachable via leader keys (=SPC b k=, =SPC f=) so they "work" through one path but
     appear broken through the palette.
   - action :: Wire them or drop them from the =commands= list (the list comment admits
     it's a "representative subset").

** [high] Web reimplements the Rust tree engine's flatten/depth-walk in TypeScript
   - note :: CORRECTED by [[file:08-frontend-backend-boundary.org][08]] (an earlier draft overstated this). The stream is NOT
     flat/out-of-order: =PubLoadEvent::Index= already carries =depth= + ordered
     =children=, parent-before-child — assembly is done in Rust and wired. The TS here
     is (a) a thin addr-keyed =StreamNode= re-accumulation for load-status tracking, and
     (b) collapse/visibility logic that is *legitimately frontend*. Optional refinement:
     stream flattened TOC rows so (a) goes away; (b) stays. Not a violation on its own.
   - where :: [[web:src/lib/wm/renderers/ReaderBuffer.svelte::863][ReaderBuffer.svelte:863-882]] (=walk()=)
   - what :: Depth-first flattening with a path-scoped cycle guard — exactly the job of
     [[src:src/tree/render.rs::1][src/tree/render.rs::visible_nodes]]. The Rust =TreeEngine=/=TreeCommand=/=TreeState=/
     =visible_nodes= system is *not referenced by api.rs or main.rs at all* (only
     =tree::state::TagEntry=, a data type; the rest is exercised solely by the module's
     own tests). The API serves =stream_publication_tree=/=load_publication_tree= from
     =publication.rs= as raw nodes; the TS rebuilds the tree.
   - why :: The central architectural promise (tree logic lives in Rust, front-ends
     consume =VisibleNode=) is *not realized*; the TS walk is a parallel, drift-prone
     implementation. (See [[file:03-tree-module.org][03]] for the Rust side.)
   - action :: Either expose =visible_nodes= over HTTP and consume it, or update the
     docs/memory to reflect that the tree command engine is currently unwired dead-ish
     code and the web owns its own flatten.

** [medium] Multi-tab "frames" model is unimplemented

     aspirational; today there's one frame.
   - action :: Mark frames as roadmap in memory, or remove the quit-frame affordances.

** [medium] openBuffers is seeded but never the source of truth for what's mounted
   - where :: [[web:src/lib/wm/buffer-store.svelte.ts::66][buffer-store.svelte.ts:66]]
   - what :: =openBuffers= tracks the global list for the switcher, but rendered content
     is =slotTrees=. =killFocused= (:294) and =cycleBufferInSlot= (:349) reconcile the

   - action :: Register =setLeaf=/=splitFocused= into =openBuffers=, or document that
     only =openBuffer()=-routed buffers are tracked.

* 6. Pattern consistency — GOOD
No legacy Svelte 4 patterns anywhere in =web/src/lib/wm/= (zero =export let=, =$:=,
=svelte/store=, =on:click=). All 15 renderers use =$props= + runes. =buffer-store= keeps
=_navHandlers= as a non-reactive =Map= with a separate =navHandlerKeys= =$state=
snapshot to avoid an effect loop (documented at :88-96) — a deliberate, correct choice.

* Themes
1. *RefsBuffer verdict:* the reference pool is built; the standalone RefsBuffer was
   intentionally retired into SearchPanel's Refs tab — the doc's "stub" prose is stale.
2. *Biggest divergence:* the web reimplements tree flatten/cycle-walk in TS while the
   Rust =src/tree= command engine is wired into nothing — the "Rust owns tree logic"
   promise is unrealized.
3. *Frames are not real:* single-singleton BufferStore; quit-frame and save-layout are
   no-op stubs.
4. *Palette drift:* ~13 M-x commands silently no-op, and =openBuffers= misses buffers
   added via split/setLeaf.
5. *Renderer hygiene is solid:* no duplicate renderers; runes usage uniform; cleanup
   items are advertised-but-absent layouts and a leftover demo seed.
