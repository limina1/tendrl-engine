** [HIGH] publish_handler and publish_blocks_handler duplicate ~130 lines of broadcast logic
   - where :: [[src:src/api.rs::2866][api.rs:2866]] and [[src:src/api.rs::3290][api.rs:3290]] (bodies at :3007-3128 vs :3442-3549)

     =begin_publish_operation=, emit =Connecting=, =publish_events_to_relays=, map
     =Accepted/Rejected=, =op.complete=, provenance =record_event_relay=, map to
     =BroadcastResult=) is copy-pasted near-verbatim across both handlers, as is the
     ingest+=sleep(300ms)=+verify block and the embedding-sync spawn.
   - why :: They have *already drifted* — different =dsl= strings ("N events" vs "N
     blocks") and different =event_ids= assembly.
   - action :: Extract =broadcast_publication(...)-> Vec<BroadcastResult>= and
     =ingest_and_verify(...)-> bool= helpers; call from both.

** [HIGH] Signing-path inconsistency: publish_blocks_handler bypasses the SigningController
   - where :: [[src:src/api.rs::3358][api.rs:3358-3407]]
   - what :: =publish_handler= signs via =build_signed_publication_events_via_signer=
     (NIP-07/46-capable through the SSE back-channel). =publish_blocks_handler= inlines
     the *legacy* secret chain: session secret → =IdentityKeyring::get_secret= →
     manual =.env= parse + =decrypt_ncryptsec=, then =build_block_publication_events(secret_hex)=.
   - why :: A user logged in via NIP-07 can publish through =/publish= but their
     =/publish/blocks= calls fall through to =None= secret and produce *unsigned events*.
   - action :: Route =publish_blocks_handler= through =SigningController= (it already
     takes the =identity= Extension; add the =signing= Extension). Delete the inline block.

     field checks; [[src:src/api.rs::4368][:4368-4373]] sign-handler =NoIdentity=/=SignerNotConnected=)

* Organization — should api.rs (4772 loc) be split?

Yes. =chat=, =identity=, =signing= are already isolated sub-routers in =main.rs=;
moving their handlers into matching files sheds ~1500 loc immediately. Suggested =api/=
module:
- =api/events.rs= — query, get_event, get_addressable, decode, search
- =api/publications.rs= — list/get/stream/sections/backfill/versions, discussions
- =api/publish.rs= — publish, publish_blocks, publish_preview, broadcast, ingest (+ the
  extracted shared broadcast helper from finding #1)
- =api/network.rs= — network status/mode/fetch-events(SSE)/fetch-confirm, fetch,
  fetch_authors, fetch_sections
- =api/config.rs= — relays, relay/info, config_update, config_snapshot, settings,
  ignore, purge, export
- =api/identity.rs= — identity_*, signer_*, sign_response
- =api/chat.rs= — chat_*

* Themes
1. *Duplication is the dominant debt* — the two publish handlers share ~130 lines and
   have already drifted.
2. *Two parallel signing worlds* — =/publish= uses the modern SigningController;
   =/publish/blocks= inlines a legacy keyring/.env chain (a correctness gap for
   external-signer users).
3. *Error-code hygiene regressed* — client/auth failures route through =Config=→500;
   the new =BadRequest=→400 is barely used; Confirm-mode gating is uneven.
4. *Roadmap is half-wired* — relay-class storage is complete and UI-exposed, but only
   the =indexer= discovery path actually routes (=broadcast_relays()=, search
   composition, =SignerCapabilities= have zero production callers).
5. *Sprawl is manageable* — only 2 truly orphaned endpoints + a NIP-46 stub; the real
   win is splitting api.rs along the boundaries the sub-routers already imply.
