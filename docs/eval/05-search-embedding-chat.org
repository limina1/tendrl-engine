* Findings (prioritized)

** [high] Entire user_data.rs module is unreachable from the binary
   - note :: RESOLUTION per [[file:08-frontend-backend-boundary.org][08]]: kind 0/3/51/65 parsing is /algorithmic event-derivation/
     and belongs in Rust. So the fix is *revive + wire* user_data.rs (and have the web
     consume it) — NOT delete it in favor of the TS client-side parsing. The
     TS-side parsing is the redundancy to remove.
   - where :: [[src:src/user_data.rs::1][user_data.rs:1-1356]]
   - what :: =UserData= is populated only via =AsyncRequest::LoadUserData= →
     =AsyncResult::UserDataLoaded=. =LoadUserData= is *never constructed* (=grep= shows
     only its def at =command.rs:893= and =.. =>= arms); =UserDataLoaded= is only
     consumed at [[src:src/tree/engine.rs::516][engine.rs:516]], never produced. No code calls =Metadata::from_note=,
     =FollowList::from_note=, etc. The web re-implements this parsing client-side
     ([[src:src/api.rs::1290][pull_user_data_handler]] just fetches raw events and returns a count;
     =RelaysBuffer.svelte= parses them in TS).
   - why :: ~1350 loc of parser + formatter + dual-path code ships dead; no warning
     because the types are =pub=.
   - action :: Decide whether the Rust-side =UserData= is the intended home (then wire
     =LoadUserData=) or delete the module + the orphaned tree plumbing. (See [[file:03-tree-module.org][03]] — this
     is part of the same TUI-era dead tier; and [[file:01-roadmap-intent-map.org][01]] data-lifecycle CLI is still open.)

** [low] naddr d-tag passed through tag_value_variants

- *No NIP-19 decode duplication* — search.rs delegates to =crate::nip19::decode= /
  =strip_nostr_prefix= ([[src:src/search.rs::717][:717-743]]); npub decode → =identity::decode_npub=.
- *Embedding dual backend shares all index/search/persistence code* — only leaf
  =embed_via_python= / =embed_via_onnx= and the =EmbeddingBackend= enum arms diverge,
  gated by =#[cfg(feature="onnx")]=.
- *SearchResult.preview 200-char truncation* ([[src:src/search.rs::492][search.rs:492]]) is not fed to any
  crypto/length-sensitive path — confirmed no violators.

* Themes
1. Dominant issue: *dead modules masked by =pub= visibility* — user_data.rs (1356) and
   drafts.rs's DraftStore/LocalPublicationTracker (590) are unreachable because the web
   took over their jobs; they compile warning-free.
2. Where a dead module's logic was needed, it was *re-implemented inline*
   (=find_profiles_matching= duplicates =Metadata=).
3. *Dual-path bloat*: every user_data type ships a "preferred" =from_note= and a
   "legacy" =from_event*=, neither called, plus debug-only fields.
4. The actively-used surfaces (parser, embedding index, chat state, llm, nip19) are
   *clean, well-tested, consistent* — no drift, chat's "no IO" holds.
5. Only one true compiler warning (the stray =file= open); rest is low-severity polish.
