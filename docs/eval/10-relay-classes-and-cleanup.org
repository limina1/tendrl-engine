** Governing principles (carry over from 09 / the boundary rule)
- *Rust* owns fetching + events + all algorithmic derivation; *TypeScript* owns
  rendering + ephemeral view state. When logic exists in both, resolve toward Rust.
- *Deliberate publishing, never spray-and-pray* (memory =project_publishing_philosophy=,
  CLAUDE.md:189/229). Relay-list edits stay *local by default*; publishing them is an
  *explicit, per-kind, user-initiated* action — never automatic on edit. Phase C3
  honors this; it does not overturn it.

* Phase C — Relay classes: make them real [0/3]

** ⇒ REFINED GOAL (2026-06-08, decided with the user) — READ THIS FIRST; it reframes everything below
The relay model is *Read / Write / Broadcast + intent*. tendrl is a *publisher's tool*,
not a social client (at least not a priority). The Amethyst-ported *discovery taxonomy is
being REMOVED, not hidden*: =search= (NIP-50), =indexer=, =named sets= (30002), the
=DiscoveryClass= default/fallback tiers, and =ExclusiveFlags=. The panel goes from ~6
concepts to 3 role-lists. Broadcast is a *maintained set*, but every broadcast runs
through the *Confirm-mode-style intent flow* — the user sees the target relays + the
events about to go out, can *modify the targets*, then confirms (same "no surprise
network" promise). This *shrinks* Phase C and turns much of it into deletion.

Net reframe (supersedes the C1/C2/C3 detail below — but that detail's file:line anchors
are still useful: they now point at *what to delete*):

- *C0 — Remove the discovery taxonomy (the bulk; subtraction).*
  - Rust: delete =DiscoveryClass= (search/indexer + default/fallback tiers),
    =ExclusiveFlags=, =compose_discovery_phases= ([[src:src/engine.rs::416][engine.rs:416]]) and its callers
    ([[src:src/api.rs::1409][api.rs:1409]]/[[src:src/api.rs::1482][:1482]]), =named_sets= (30002) + the named-set endpoints, and the
    discovery-kind pull path ([[src:src/api.rs::1480][api.rs:1480]] — keep *10002* only, drop 10007/10086/10088/
    30002). Collapse =RelaySets=/=RelayConfig= to *read* (= today's =general= + =fetch=) +
    *write* (= =publish=) + *broadcast*. The B1 =discovery_sibling= helper
    ([[src:src/relay_store.rs][relay_store.rs]]) becomes dead — remove it; =urls_mut= simplifies to 3 arms.
  - Web: delete the search/indexer rows, the named-sets section, and the
    pull-from-profile suggestion UI for 10007/10086/10088/30002 in
    [[web:src/lib/wm/renderers/RelaysBuffer.svelte][RelaysBuffer.svelte]]. *This removes the just-merged 30002/pull work (=ce65412=,
    =6662fb1=) — confirmed-by-elimination with the user; double-check on resume.*
- *C1 — Wire Read / Write / Broadcast.* =Read= drives all fetch/read paths;
  =Write= (=publish_relays=) drives publishes; =Broadcast= finally gives
  [[src:src/engine.rs::310][broadcast_relays()]] a home — the explicit broadcast action targets it
  (empty → fall back to write), *through the intent flow*. Map engine sets:
  =general=+=fetch=→read, =publish=→write, =broadcast=→broadcast.
- *C2 — Persist* read/write/broadcast round-trip (relays.json + config.toml). Verify.
- *C3 — Relay-list publishing (mostly ships).* Keep *10002* (NIP-65 read/write — the
  real "sync my relays to my other apps"); boundary-fix its public-tag construction into
  Rust. *Decide:* does Broadcast publish a list at all? With discovery gone, the
  encrypted 10088 broadcast-list kind is probably not worth keeping → broadcast likely
  stays a *local-only* set, no published event. Drop 10007/10086 (deleted). Land the
  CLAUDE.md philosophy-wording amendment here.
- *Broadcast-with-intent* (the user's emphasis): the broadcast action reuses the
  Confirm-mode =RequestSummary= modal (which relays + which events) and lets the user
  *edit the target relays* before confirming. Largely exists via the publish Confirm
  modal — wire broadcast to it + expose target editing.
