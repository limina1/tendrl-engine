** Governing principles (carry over from 09 / the boundary rule)
- *Rust* owns fetching + events + all algorithmic derivation; *TypeScript* owns
  rendering + ephemeral view state. When logic exists in both, resolve toward Rust.
- *Deliberate publishing, never spray-and-pray* (memory =project_publishing_philosophy=,
  CLAUDE.md:189/229). Relay-list edits stay *local by default*; publishing them is an
  *explicit, per-kind, user-initiated* action — never automatic on edit. Phase C3
  honors this; it does not overturn it.

its standard kind so "sync to all my apps" works: *10002* (NIP-65 read/write), *10007*
(search), *10086* (indexer), *10088* (broadcast), *30002* (named sets).

- [ ] *C1 — Route the classes in-app (the phantom fix).*
  - =broadcast=: wire [[src:src/engine.rs::297][engine.broadcast_relays()]] (currently *0 callers*) into the
    broadcast action so it targets the broadcast set, not =publish_relays()=.
  - =read= / =write= (NIP-65 semantics): confirm reads consult read relays and publishes
    consult write relays; repair routing where they collapse onto =fetch=/=publish=.
  - =search=: route search queries through search-class relays —
    =compose_discovery_phases("search")= ([[src:src/engine.rs::443][engine.rs:443]]) exists but =search_handler=
    ignores it (only =indexer= composition is consulted today).
  - =indexer=: wire as a fetch-path fallback on read-miss — [[src:src/engine.rs::559][engine.relays()]] returns
    only =fetch.urls= today, so indexer is targeted for profile/metadata backfill but
    not generic fetch. Closes *T33* ([[../user_testing.org][user_testing.org]]).
- [ ] *C2 — Persist to config (the "saving to config" ask).* =relays.json=
  ([[src:src/relay_store.rs][relay_store.rs]]) is already the authoritative *live* set, and Settings → Save
  writes the working sets into config.toml ([[web:src/lib/wm/renderers/SettingsBuffer.svelte][SettingsBuffer.svelte]]). Verify all five
  classes round-trip through *both* (live state file + boot config); fill any gaps so a
  reload and a reboot both restore the same class assignments.
- [ ] *C3 — Per-kind opt-in relay-list publishing (the "broadcast to all my apps"
  ask).* A *granular, per-event-kind* publish action — *not* one bulk button. For each
  class the user can choose to publish *that kind only*:
  | Class        | Kind  | Tag shape                         |
  |--------------+-------+-----------------------------------|
  | read/write   | 10002 | =r= tags + read/write marker (NIP-65) |
  | search       | 10007 | =relay= tags                      |
  | indexer      | 10086 | =relay= tags                      |
  | broadcast    | 10088 | =relay= tags                      |
  | named sets   | 30002 | =d= + =relay= tags (NIP-51)        |

  action with its own confirm.* *Never* automatic on edit (the philosophy). Note the
  read-side parse of these kinds already exists ([[src:src/api.rs::1440][api.rs:1440]] documents 10002/10007/
  10086/10088/30002, =RelaysBuffer= imports them); this adds the *write* path. The
  private-member (NIP-44) variant of 30002 stays deferred (T32 — signer-dependent).
