   three-panel Chat/Compose/Search layout with =PanelFocus= and =Alt+1/2/3=.
   features.md / wm-shell.md say this is *retired*. features.md/wm-shell.md win.
2. *Directional glyphs are dead layout.* reference-pool-worksheet explicitly notes the
   =◂=/=▸= "push left/right" glyphs (still in workbench-arch Search Actions) "mean
   nothing now that WM buffers have no fixed position."
3. *RefsBuffer: standalone vs SearchPanel tab.* workbench-arch + wm-shell Phase 1
   describe a standalone =RefsBuffer.svelte=; it was collapsed into a Refs tab inside
   SearchPanel. The "RefsBuffer is the pool's neutral view" prose is now inaccurate.
4. *Semantic backend: SQLite vs usearch.* workbench-arch specifies SQLite + sqlite-vec
   + fastembed. What shipped is *usearch HNSW + Python sidecar / ONNX*. The entire
   "Sidecar Storage (SQLite)" subsection is superseded design that was never built.
5. *"Online/Offline" vs "Auto/Confirm".* data-lifecycle + project-summary say
   Online/Offline; network.rs/CLAUDE.md rename to Auto/Confirm. Same toggle.
6. *Phase numbering collision.* "LLM tool calling" is Phase 6 in workbench-arch but
   Phase 7 in project-summary. Git uses =phase1=–=phase6= for the unrelated relay/
   discovery work. Three independent "phase" numbering schemes coexist.
7. *features.org vs features.md* — same title, both labeled CURRENT, 9 days apart,
   contradicting on layout. =.md= is authoritative.

* 5. The current north star

By recency (May 13–27 docs + git tip), the project is converging on *making the
WM-shell web UI a complete, trustworthy single-user knowledge workbench* — not
multi-user or LLM autonomy yet. Live fronts:

1. *Relay management as a first-class, legible surface* — newest commits are the
   Confirm-mode publish/broadcast modal and fetch-gating polish (the "no surprise
   network" promise).
2. *Publishing that replaces instead of forks* ([[doc:republish-diff.md][republish-diff]], newest doc) + nested
   30040/30041 graphs — deliberate, non-duplicative publication as the core loop.
3. *Discussions read→write* — next push is comment/highlight *authoring*.
4. *Reference Pool maturation* — held-set → citation substrate (NKBIP-03), still in
   the decision-locking stage.

Explicitly *not* the current focus: multi-user (DRAFT, no code) and LLM tool calling
(untouched). Near-term north star: a single user can search, hold/reference,
deliberately (re)publish nested NKBIP-01 publications, discuss them, and control
exactly which relays see what — all inside one tiling-WM web shell with confirm-gated
networking.
