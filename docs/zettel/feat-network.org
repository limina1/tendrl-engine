#+TITLE: Network Modes & Fetch Policy
#+TYPE: feature
#+STATUS: implemented
#+DATE: 2026-07-05

Local-first network control: the user decides when the engine talks to
relays, per-query (fetch policy) and globally (network mode). Nothing hits
the network without either a policy that allows it or an explicit approval.

* What exists
- =FetchPolicy= (=src/engine.rs=): =LocalOnly= (nostrdb only, instant,
  offline), =LocalFirst= (local, then relay backfill if under limit — the
  default), =FetchAlways= (always hit relays, merge with local).
- =NetworkMode= (=src/network.rs=): =Auto= — user-initiated relay fetches run
  automatically; =Confirm= — every user-initiated fetch emits an *intent* the
  UI must approve before the engine proceeds. Note: older docs called these
  "Online" / "Offline"; =Auto= / =Confirm= are the current names.
- Intents + live fetch activity stream to clients over SSE
  (=GET /fetch-events=); approval via a confirm endpoint;
  =GET /api/v1/network/status= / =POST /network/mode= for state.
- =FetchGuard= RAII tracks in-flight relay requests in a ring buffer
  (=NetworkActivity=) so the UI shows live activity.
- Web: network-mode toggle in the header, modeline network pill with a
  pulsing "fetching" dot, =FetchConfirmModal= and =FetchActivityModal=
  (=web/src/lib/network/=, =web/src/lib/components/=). The AI assistant's
  =fetch_from_relays= tool gates through the same Confirm flow.

* The intent pattern (the app's Confirm-mode surface)
The unit the UI approves is an *intent*: a user-initiated action emits a
structured "here is what I'll fetch and from where" *before* touching the
network; Confirm mode gates on it, Auto passes it through as an informational
toast. One shape, several callers — this is the place to track them:
- *Fetch intent* (=FetchEvent::Intent=, =begin_operation_with_summary=): a REQ.
  Carries the proposed relay set + a =RequestSummary= (filters / composition /
  DSL sentence). =FetchConfirmModal= renders it; the user drops/adds relays and
  =ConfirmDecision.relays= overrides the set the engine uses.
- *Publish intent* (=FetchEvent::PublishIntent=): the broadcast counterpart —
  carries the event ids + destination relays so the UI correlates per-relay
  Accepted / Rejected.
- Nostrdown =embed= / =quote= / =slot= entity fetches ride the *fetch* intent
  (=FetchAlways= → Confirm), which is why a not-local reference's relay pull
  surfaces here — see [[file:feat-nostrdown.org][nostrdown]].

Open refinements:
- [[file:idea-entity-hinted-relay-intent.org][Entity-hinted relays in the intent]]
  — a =naddr= / =nevent= carries relay hints in its NIP-19 TLV; surface them in
  the modal *distinctly* (grouped/highlighted as "this reference points here") and
  offer a hinted-relay(s)-vs-full-set choice.

* Gaps / open edges
- No per-source or per-kind fetch policies — the mode is engine-global.
