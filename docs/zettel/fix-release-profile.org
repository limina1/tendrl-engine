* The issue (observed 2026-08-12, v0.8.2)

There is *no* =[profile.release]= anywhere: not in the root =Cargo.toml=,
and not in =mobile/src-tauri/= — which is deliberately outside the root
workspace and is therefore its own workspace root inheriting cargo
defaults (=opt-level 3=, *no LTO*, =codegen-units 16=, =strip none=,
=panic unwind=). Measured consequences:

- Desktop release binary: 59 MB.
- =libtendrl_mobile_lib.so= in the shipped APK: *44.4 MB, not
  stripped* (verified via =file= on the APK entry) — ~60% of the 72 MB
  APK. Gradle's =isMinifyEnabled= is R8 on the dex and does nothing for
  the native lib. Native libs ship uncompressed (16 KB page alignment),
  so install size ≈ the full 75.8 MB.
- The mobile risk register's mitigation "strip + LTO as in release
  profile" referenced a profile that did not exist (corrected in
  [[file:feat-mobile.org][the mobile zettel]], 2026-08-12).

Adjacent build-hygiene tax: rust-embed doesn't watch =web/build/=, so
=build-android.sh= forces =cargo clean -p nostr-engine= — a *full engine
recompile on every APK build*.

* Proposed fix

- [X] =[profile.release]= in both workspace roots: =lto = "thin"= (try
  =fat= and compare), =strip = true=, =codegen-units = 1=
- [X] +=panic = "abort"= for the mobile workspace+ — *rejected*: the
  engine deliberately spawn-isolates the background embed pass
  (=server.rs:722=) because an on-device ONNX panic was observed killing
  the loop silently; =abort= would turn that survivable panic into app
  death. Revisit after
  [[file:fix-embedding-runtime-blocking.org][embedding runtime blocking]].
- [X] Rebuild, record binary/APK size deltas here — desktop
  =tendrl-engine= (SPA embedded): 59.2 MB → 48.6 MB thin LTO → *47.2 MB
  fat LTO* (−20%); thin vs fat build time was a wash (7m02s vs 7m40s
  clean), so both manifests ship =lto = "fat"= (drop to =thin= if an
  NDK link ever chokes). APK/.so deltas (signed build, 2026-08-12,
  fat LTO): APK 72 MB → *55 MB* (−24%);
  =libtendrl_mobile_lib.so= 44.4 MB unstripped → *26.8 MB stripped*
  (−40%). Fat LTO linked clean under NDK r28c.
- [X] =cargo:rerun-if-changed= on =web/build/= (build script) to drop
  the forced clean — *already existed*: =build.rs:50-64= walks the tree
  and emits per-file rerun-if-changed (the claim above was stale).
  Verified from the mobile workspace's separate target dir (touch an
  asset → nostr-engine recompiles), so the forced
  =cargo clean -p nostr-engine= in =build-android.sh= is deleted — this
  was a full engine recompile on every APK build.
