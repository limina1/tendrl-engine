#+TITLE: Idea: highlighters — labelled, coloured highlight events
#+TYPE: idea
#+STATUS: design — model settled 2026-11-11 (labels as events, like writing styles); prototype next
#+DATE: 2026-11-11

* What it means

A highlight today (kind 9802) carries the text, context, an optional
note and its source — no /function/, and its colour is only the
yours/theirs theme tint. A *highlighter* is a label paired with a
colour: =vocabulary=, =for=, =against=, or anything the reader names.
Highlighting with one marks /what the passage is/, and the reader paints
it in that highlighter's colour.

* Highlighters are events, like writing styles

Same pattern as the annotation requests' writing styles
(=src/api/styles.rs= on =feat/annotations-table=): a style is a kind-30078
event (=t: tendrl-style=, =title=, instructions as content), the picker
lists the style events found in the store, a new one can be written
inline, and a request names its style by coordinate (=["style", …]=) so
"everything in this style" is one tag search.

A highlighter is the same shape:

#+begin_src
kind 30078 (NIP-78 app data, addressable)
["d", <nanoid>]
["t", "tendrl-highlighter"]
["title", "against"]
["color", "#ff6b6b"]
content: what this label means — "a passage that argues against the thesis"
#+end_src

and a highlight names it by coordinate:

#+begin_src
kind 9802
["highlighter", "30078:<pk>:<d>"]
#+end_src

So the label set is picked up from existing events, not a fixed list:
- the colour travels on the highlighter event (no separate palette);
- "everything highlighted /against/" = =#highlighter= search;
- the content tells a reader — or the assistant — what to mark with it;
- local until broadcast, newest version per coordinate wins.

* The picker

- *Your highlighters* — highlighter events signed by you, from the store.
- *Use another's* — a separate button: enter an npub, fetch that
  reader's =t: tendrl-highlighter= events (Confirm-gated like any relay
  fetch), and highlight with theirs. A highlighter referenced by a 9802
  already in the store is discovered the same way.
- *New highlighter* inline: title, meaning, colour.

* Colour

Chosen when the highlighter is made (or edited — a new version):
- *Standard*: a dropdown of the standard highlighter colours (yellow,
  green, blue, pink, orange, purple …).
- *Custom*: a button beside the dropdown pops up an HSV colour picker.
- Default when none is picked: a stable colour from the title hash.

* Reader

Highlight resolution (=POST /api/v1/highlights/resolve=) carries the
highlighter coordinate through; the engine resolves it to title + colour;
the overlay paints spans in that colour; the highlights drawer filters by
highlighter (only =against=, only another reader's =vocabulary=).
