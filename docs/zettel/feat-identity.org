#+TITLE: Identity & Signing
#+TYPE: feature
#+STATUS: implemented
#+DATE: 2026-07-05

Nostr key management and event signing. The engine is the signing
orchestrator: callers hand it an =EventTemplate= and get a =SignedEvent= back
without knowing where the key lives.

* What exists
- Key formats (=src/identity.rs=): npub (read-only), nsec (discouraged),
  ncryptsec — NIP-49 encrypted secret (scrypt + XChaCha20-Poly1305), the
  default flow. Password decrypts in memory only.
- OS keyring stores the *encrypted* blob (never the plaintext key); optional
  session restoration on startup. *Backend (2026-09-17):* a real
  platform backend is compiled in — Secret Service over D-Bus on Linux
  (=sync-secret-service= + =crypto-rust=; gnome-keyring, KDE ksecretd or
  KeePassXC serve it), =apple-native=, =windows-native=; entries under
  service =nostr-engine=. The user's ncryptsec, the assistant's identity
  and either slot's bunker pairing survive a restart; the portable build
  vendors libdbus (=--features keyring-vendored=). The 2026-09-16 "no
  backend" call was reversed — see
  [[file:decision-no-keyring-backend.org][the superseded decision]].
- Idle-lock timer: the signer auto-locks after configurable inactivity;
  auto-signing while unlocked means publish flows don't re-prompt mid-session.
- Endpoints: =GET /api/v1/identity= (none / locked / unlocked),
  =/login=, =/lock=.
- Pluggable =Signer= trait (=src/signing.rs=): =InProcessSigner= (engine
  ncryptsec); NIP-07 (browser extension) and NIP-55 (Amber, Android) over
  the SSE registry; *NIP-46 bunker* (2026-09-16) — the engine is the
  client: =src/bunker.rs= (=BunkerSigner=, relay transport with reconnect),
  =src/nip46.rs= (URI, request/response, 24133 envelope), =src/nip44.rs=
  (v2 encryption, spec vectors). Endpoints =POST /api/v1/identity/bunker/
  connect {uri}= · =/reconnect= · =/disconnect=, =GET /identity/bunker=;
  the pairing (URI + transport key) persists in the keyring and
  =[identity] source = "nip46"= reconnects on boot. Settings → Source →
  "bunker (nip46)" pastes the URI; =auth_url= approvals show a link + retry.
  [[file:decision-bunker-engine-is-the-client.org][Decision]].
- Named signing source on publish (2026-09-16): =/api/v1/publish= takes
  =sign_as: "user" | "assistant"= (=sign: true= = user); the assistant path
  resolves =Engine::assistant_signer()= — its own session, never the user's.
  [[file:decision-assistant-signs-own-key.org][Decision]].
- Web: ncryptsec entry modal; identity badge in the modeline
  (=web/src/lib/identity/=).
- =AuthSigner= (=src/signing.rs=): the one capability the relay client
  holds — it can sign *only* kind-22242 NIP-42 auth events, through the
  =SigningController= so every source (engine key, NIP-07, NIP-55) is
  covered and the assistant identity never authenticates. The third
  signing purpose next to snapshot and broadcast: no stored event — 2026-09-15,
  [[file:decision-nip42-auth-as-user.org][decision]].

* Gaps / open edges
- NIP-46: =bunker://= only — the client-initiated =nostrconnect://= (QR)
  flow is not implemented; NIP-04-only bunkers are unsupported by design.
- NIP-49 decryption passes official test vectors but may hit edge cases with
  some external implementations (noted in =docs/features.org=).
