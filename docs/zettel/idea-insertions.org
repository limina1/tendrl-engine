#+TITLE: Idea: insertions — reader-attached sections
#+TYPE: idea
#+STATUS: plan
#+DATE: 2026-09-16

* What it means

NKBIP-01 assumes a book is constructed /a priori/: the 30040 index says
what is in it. A physical book is not like that — it takes post-it
notes, slips taped between pages, marginalia — matter that is /attached
to a place/ without being /part of the structure/, and that an editor
may later fold in. Highlights (9802) quote a place; comments (1111)
discuss it; nothing yet /adds structured text/ at it.

An *insertion* is a kind-30041 section carrying NIP-22's root/parent
anchor tags (=A=/=K=/=P= for the publication, =a=/=k=/=p= for the section
it attaches to) plus one new tag, =["insert", "before"|"after"]=, that
turns a margin /annotation/ into a sequence /insertion/. Spec:
[[file:../../nips/NKBIP-01-insertions.org][NKBIP-01 insertions extension]].

The general thing this names: *a reader-curated collection that is not
yet official structure*. The context pool, a saved chat, an
assistant-synthesized zettel, a post-it — the code has treated each as
its own ad-hoc mechanism. Insertions are the first one with a wire
format.

* Data

- 30041 + =A=/=K=/=P= + =a=/=k=/=p= (+ optional =e= version pin, as 9802
  does) + optional =insert=. All within NKBIP-01's "additional tags MAY
  be included". No new kind.
- Discovery: ={"kinds":[30041], "#A":[coordinate]}= — the comment
  loader's filter shape; =A= is a coordinate, not 64-hex, so nostrdb
  treats it as an ordinary tag.
- Promotion: NKBIP-01 as written — the owner republishes the 30040 with
  a new =a= tag (=auto-update= governs followers); anyone else publishes
  a derivative index (=p= + =E=). The insertion event never changes.
- Standalone notes (a kasten): root = the note; promotion = the note's
  author refs it, or it enters a collection.

* Representation (engine)

- =src/publication/insertion.rs= — pure: parse anchor tags, emit them,
  classify annotation vs insertion, compute promotion slot from
  =insert= + the parent's index position.
- =build_insertion_template= beside =build_highlight_template=
  (=src/discussions.rs=): the same three-family shape — the anchor is
  a =HighlightSource::Event=-like target, but the /content is new/.
- =load_insertions(root, authors)= — on demand, Confirm-gated, never a
  pass inside the tree loader ([[file:decision-insertions-load-on-demand.org][decision]]);
  returns each with its anchor so the reader can draw the pointer.
- =fork_index(index, splice)= — the promotion /copy process/: every tag
  copied verbatim, the insertion's =a= spliced at its slot; same =d= if
  the logged-in author owns the index, else a new =d= + =p= + =E= to the
  copied index. One template, the existing publish path.
- Assistant-authored: signed by the assistant slot
  ([[file:decision-assistant-signs-own-key.org][decision]]); =by:assistant=
  filters them.

* UI/UX

- Reader: a *load annotations* action fetches them; each renders
  /pointing at/ its anchor section — symbolic of a post-it stuck to the
  page, not absorbed by it. The visual language is a design session,
  not a retrofit. /Promote/ on one runs the fork process and opens the
  publish flow on the copied index.
- The *zettel bubble*: from a focused section, "write more from this"
  → engine assembles context (the section, siblings, resolved refs,
  HNSW neighbours) → one =run_turn= with a structured-output schema
  shaped like =ComposeState= → an insertion template signed by the
  assistant → appears anchored, pending, in the reader. Review-first
  variant lands in =DraftStore= instead.

* Open questions

- Tag name =insert= — fine, or single-letter for relay indexing? User decision: Yes
  Position is never queried, so a word is the honest choice.
- Do promoted insertions keep their anchor tags? Default yes — they
  record that the section entered by insertion. User response: They are 30041 authored events, they conform to the spec and can be inserted without dropping any tags
- Several insertions at one position: =created_at= order, curator
  resolves at promotion. user: yes
- Span anchoring stays out — same problem as
  [[file:idea-annotation-anchoring.org][annotation anchoring]].
