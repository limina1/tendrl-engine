#+TITLE: WM Shell
#+TYPE: feature
#+STATUS: implemented
#+DATE: 2026-07-05

The web UI's frame: an Emacs/i3-flavored tiling window manager. Everything in
the app is a buffer living in a class-typed slot, driven by vim-style modal
navigation. Full spec: =docs/wm-shell.md=; shell root in
=web/src/routes/+page.svelte=, machinery under =web/src/lib/wm/=.

* What exists
- Class-typed slots: =chat= (left), =work= (center — feed/reader/composer/
  profile/ignored), =research= (right — search/kb/refs). Each slot is =open=
  or =rail= (collapsed bar); one base layout, collapsible on the fly.
- Stable-ID buffers: =reader:30040:<pk>:<dtag>=, =reader:event:<id>=,
  =composer:current=, =draft-reader:current=, =profile:<pk>=, plus singletons
  (=chat=, =feed=, =search:default=, =settings=, …). Registry + renderers in
  =web/src/lib/wm/registry.ts= and =web/src/lib/wm/renderers/=.
- Splits: =SPC w s= splits the focused leaf with a same-class buffer picker;
  =j= / =k= cycles leaves. Buffer switching =SPC b b= (class) / =SPC b B=
  (global) / =SPC b r= (recently closed, cap 20); =SPC b k= kills.
- SPC leader with Doom-style which-key popup; M-x fuzzy command palette
  (=:=); modeline with layout, focused buffer, and segmented network /
  embedding / identity status pills.
- Modal nav: normal/insert modes; editable focus implies insert, Esc / =C-[=
  / =C-g= escape; ranger cursor (=j=/=k=, =gg=/=G=) across feed, reader,
  search, compose; =h= / =l= drill axis per buffer.
- Multi-frame model: multiple tabs share one global buffer list; layouts and
  windows are per-frame (Emacs frame semantics).

* Gaps / open edges
- Per =docs/wm-shell.md=: deep-link routing (=/p/<pk>/<dtag>= → buffer),
  cross-tab BroadcastChannel sync, user-savable perspectives, and Shell
  extraction into a reusable component are still open.

* Constraints when building buffer features (learned the hard way, 2026-07-06)
Two non-obvious traps in the buffer render path — each cost multiple
reader-breaking iterations. Anything mounting *inside* a buffer must respect them:

- *No component-lifecycle hooks.* =getContext= / =setContext= / =onDestroy= throw
  =lifecycle_outside_component= when a buffer mounts — the render path doesn't
  establish a reliable component-init context. Share per-buffer state by
  *prop-threading* it down, and clean up with an *=$effect= teardown return*,
  never =onDestroy=. (This is why the reader's resolution-progress tracker is
  passed as a prop, not a context — see [[file:feat-nostrdown.org][nostrdown]].)
- *No import cycles through =wm/registry=.* =registry.ts= imports every buffer
  renderer, so a component that imports =registry= closes a cycle that throws
  =Cannot access <X> before initialization= — but *only under =--build=* (bundled
  module-init order); =--dev= (native ESM) hides it, so it reads as a
  "renders differently in dev vs build" ghost. Keep shared metadata in *leaf
  modules* a component can import without dragging in the renderers (e.g.
  =wm/tours.ts= holds the tour/class data; =ComposeView= imports *that*, not
  =registry=).
