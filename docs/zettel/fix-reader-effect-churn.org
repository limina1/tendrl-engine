* The issue (observed 2026-08-12, v0.8.2)

=ContinuousView='s two resolve effects (=ContinuousView.svelte:67=,
=:135=) depend on (a) the =sections= array, freshly allocated by every
rAF stream commit, and (b) =app.networkStatus=, which a 2 s poll
reassigns with *no equality guard* (=state.svelte.ts:4169-4184=; the
effects read =app.networkStatus?.mode= synchronously). Consequences:

- During a stream: up to one full-document =/highlights/resolve= +
  =/nostrdown/parse= round trip per animation frame.
- At steady state: both POSTs re-fire *every 2 seconds, forever*, per
  mounted reader. Only =/nostrdown/resolve= is session-cached
  (=api.ts:358=); =parseNostrdown= (=api.ts:479=) and =resolveHighlights=
  (=api.ts:298=) have no cache at all.
- The effect resolves every *loaded* section, not every *visible* one
  (=ContinuousView.svelte:143= ignores the collapse model).
- A second, independent network-status poll runs at 5 s / 1.5 s
  (=+page.svelte:397=), not =document.hidden=-guarded.
- Draft previews are worse: excluded from the cache (=api.ts:361=), the
  composer's =DraftReader= re-runs a full =local_only= *and* a
  relay-reaching =local_first= resolve on every tick and keystroke.

Same family as the fixed profile-query flood (bounded, not infinite —
but it is the single largest network amplifier in the reader path).

* Proposed fix

- [X] Equality-guard the status poll (only reassign =networkStatus= on
  change), and/or read =mode= via =untrack= in the resolve effects —
  JSON-compare guard shipped (the payload is byte-stable at idle);
  =mode= stays *tracked* via the effect keys on purpose, preserving
  "flip to Auto → one backfill of already-rendered sections"
- [X] Session-cache =parseNostrdown= and =resolveHighlights= exactly as
  =resolveNostrdown= is cached — content-fingerprint keys (highlight
  side keyed by the sorted 9802 id set; the events are immutable);
  =SectionCard= and =DraftReader= benefit with zero edits
- [X] Key the effects on a stable addr-set identity, not array identity
  — =hlEffectKey= / =ndEffectKey= derived strings (value-compared, so
  per-frame array reallocation stops re-firing the POSTs); item builds
  run under =untrack=
- [X] Resolve visible-first (respect the collapse model; backfill the
  rest idle) — the nostrdown batch splits on =visibleRows= membership;
  the hidden remainder resolves via =requestIdleCallback=.
  Collapse/expand is deliberately NOT in the effect key: expansion
  needs no re-run because the remainder already resolved.
- [X] Collapse the duplicate 5 s poll into the 2 s one — the pill now
  derives from =app.networkStatus=; a 1.5 s local poll runs only while
  the activity popover is open (visible by definition)
- [X] Cache draft resolves with invalidation on edit — shipped by the
  [[file:fix-resolve-cost-model.org][cost model]] key rework
  (fingerprint keys; drafts no longer opt out)
