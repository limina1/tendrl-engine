#+TITLE: MCP Surface
#+TYPE: feature
#+STATUS: implemented
#+DATE: 2026-09-16

tendrl as a tool server for an /external/ agent harness — Claude Code,
Codex, anything speaking MCP. The harness brings its own credential and
runs on the user's machine; tendrl holds no LLM key on this path. This
is the only sanctioned way a user's claude.ai subscription reaches
tendrl: Anthropic's Agent SDK terms disallow third-party apps offering
claude.ai login or rate limits, so the in-app loop runs on *agent
services* (ppq.ai / routstr — [[file:feat-assistant.org][AI assistant]];
the engine holds no Anthropic key at all since 2026-09-22) and the Claude
path is always "your harness calls tendrl", never "tendrl calls Claude".

* What exists (2026-09-17, plan Phase 4 — branch =feat/engine-mcp=)

The engine speaks MCP itself: =src/mcp.rs= serves *Streamable HTTP* on
=http://127.0.0.1:<port>/mcp= (spec 2025-06-18 / 2025-03-26 / 2024-11-05;
stateless — JSON responses, =202= for notifications, =405= on =GET=, no
session id). =tools/list= is =tools::definitions()= under the *same live*
=ToolPolicy= the chat pane uses (Settings → AI tools), =tools/call= is
=tools::dispatch()= with the same =ToolCx= (engine + the engine-owned
context set) — one catalog, 21 tools, no second table. A tool failure
comes back in-band (=isError=); an unknown or disabled tool is a
JSON-RPC =-32602=. Results carry =structuredContent= next to the text.

- *Auth*: bearer token — =[mcp] token= in config, else minted once into
  =<data_dir>/mcp-token= (0600) and reused every boot; the Android host's
  loopback token also passes. =GET /api/v1/mcp= returns the URL, token,
  enabled tools and the ready-made =claude mcp add --transport http …=
  line (the desktop API is unauthenticated, so this reveals nothing new).
  Settings → AI tools shows the same with a Copy button. =[mcp] enabled =
  false= turns the endpoint off.
- *Confirm mode applies unchanged*: a =fetch_from_relays= or a broadcast
  from an MCP call raises the same intent modal in the app — the gating
  lives in the engine, below the transport.
- =scripts/tendrl-mcp.py= is now a ~50-line *stdio → HTTP shim* with no
  tool table (=TENDRL_MCP_URL=, =TENDRL_MCP_TOKEN=; the token is fetched
  from =/api/v1/mcp= when unset) for harnesses that only launch stdio
  servers. =.mcp.json= keeps pointing at it, so the checked-in config
  stays portable; the direct HTTP registration is one command away.
- What a terminal agent sees: =get_context= (the set curated in the app),
  =search_events= / =semantic_search=, publication readers, and the
  assistant-signed writers — =propose_insertion= (attached, pending),
  =save_draft= + =sign_draft=. The =publish= / =promote_insertion= /
  =sign_draft= trio stays off until switched on in Settings.

* Answering requests

Annotate mode's "ask for notes" writes a local request record; the
=/tendrl-requests= skill (=docs/skills/tendrl-requests/=) is the loop a
Claude Code session runs when the user says "check tendrl requests":
=list_requests= → read the anchor (=get_addressable=, =view_publication=,
=semantic_search=, =get_context=; web search is the harness's own) →
=propose_insertion= per note → =answer_request=. tendrl never initiates
([[file:decision-requests-are-events.org][decision]]).

* Verified

Live on a scratch engine (recipe: [[file:../commands.org][commands.org]],
"MCP"): initialize echoes the client's protocol version; =tools/list=
follows a Settings toggle without restart; =tools/call add_to_context= →
the app's Context panel shows the entry; an unauthenticated POST is
=401=; the shim relays a full initialize / list / call session over
stdin. Parallel =tools/call= fan-out measured — see the recipe for the
numbers and the nostrdb-mutex note.

* Next (Phase 5c, [[file:feat-notifications.org][notifications]])

=list_asks= (what is for the user, under their notification kinds),
=get_ask_diff= (the engine's structured diff for an 818), =review_ask=
(a structured *result* kept as a local record — not an event; the
assistant never comments on others' merge requests under its own key),
=prepare_merge= (the owner's next version as an unsigned draft),
=fetch_asks= (Network, Confirm-gated). No =merge_ask= / =decline_ask=:
merge, decline, relink and the 818 are always the user's key. The
=/tendrl-requests= skill grows a vocabulary branch (one
=propose_insertion= per term, =role: definition=) and a merge-request
branch. Still a pull: nothing wakes the agent.
