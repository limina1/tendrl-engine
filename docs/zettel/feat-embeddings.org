#+TITLE: Embeddings
#+TYPE: feature
#+STATUS: implemented
#+DATE: 2026-07-05

Semantic search over the event corpus, fully in-process — no sidecar, no
external service. Vectors are computed by an ONNX model and stored in an HNSW
index; the =~:= search operator queries it.

* What exists
- =src/embedding.rs=: usearch HNSW index persisted to =vectors.idx= +
  =vectors.map=; in-process ONNX embeddings via fastembed. The model loads
  lazily on first embed, is cached on disk (=<data_dir>/fastembed_cache=), and
  the release build ships it beside the binary.
- Search integration: =~:concept= / =~:"phrase":k= (default k=10) in
  =src/search.rs=; over-fetches k×10 from HNSW when kind/author filters are
  present, then post-filters.
- Endpoints: =GET /api/v1/embed/status= (model health + index size),
  =POST /api/v1/embed/sync= (incremental), =POST /api/v1/embed/reindex= (full).
- Background task in =src/main.rs=: embeds new events (and fetches missing
  sections) on a 60-second interval when embeddings are enabled.
- Web: reindex button + live event-count indicator in settings
  (=web/src/lib/components/EmbeddingSettings.svelte=); score badges on
  semantic results; embedding pill in the modeline.

* Gaps / open edges
- Per-event =sync_embeddings()= is slow on large batches; bulk JSONL ingest
  works around it with a single sync at the end.
- Performance (2026-08-12 audit): +the 60 s sync pass rescans up to 100k
  events per tick with no watermark and rewrites the full index every 32
  embeds+ — fixed same day
  ([[file:fix-background-tick-idle-cost.org][fix-background-tick-idle-cost]]:
  ingest-fed dirty set, one reconciliation scan per boot, saves every
  512 inserts, compact =vectors.map=, in-flight guard);
  +ONNX inference runs synchronously on tokio workers and =~:= can inline
  the model download+ — also fixed same day
  ([[file:fix-embedding-runtime-blocking.org][fix-embedding-runtime-blocking]]:
  inference on the blocking pool everywhere, =~:= fails fast while the
  model downloads in the background, and the new
  =embedding.max_per_tick= budget trickles backlogs — the mobile host
  defaults it to 64/tick).
