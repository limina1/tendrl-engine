#+TITLE: Decision: The engine owns provider credentials
#+TYPE: decision
#+STATUS: current
#+DATE: 2026-09-22

* The decision

Agent-service accounts — the ppq credit id + key, the routstr node + key,
the active choice, ceilings — live in =<data_dir>/providers.json= (mode
0600), written and read only by the engine. The API returns keys
*redacted* plus a one-shot reveal for copying. Nothing goes to browser
storage, TOML, the environment or a Nostr event. Same file on desktop and
Android; the OS keyring is a possible later hardening for the desktop key,
not a v1 requirement.

* Why

- *The engine makes the calls.* Every agent turn is the engine talking to
  the provider, so the credential must be readable by Rust. Keeping it in
  the WebView would mean shipping it back on every request — the wrong
  side of the frontend/backend boundary and one more place to leak.
- *Android's sandbox is the right home.* The engine runs in-process; its
  data dir is app-private, wiped on uninstall, and survives a WebView
  storage reset (which =localStorage= would not).
- *One recovery story.* A ppq account is recoverable by its credit id, a
  routstr key by its node + key — both shown once, both re-adoptable
  through "I have a key". No keyring-vs-file split to explain.

* Consequences

- =providers.json= is a secret file: never committed, never synced, never
  read by the SPA. Backups of the data dir carry it.
- =reveal= is a deliberate, one-shot endpoint; the drawer, mode-line and
  Settings only ever show =sk-abc…(25)=.
- The routstr *withdraw* token is returned once and not stored — it is
  the user's money, handed to their wallet immediately.
