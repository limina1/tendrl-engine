* What it means

NIP-A7 (draft) defines kind-777 "spells": a Nostr event that encodes a
single REQ/COUNT filter as tags, with runtime variables (=$me=,
=$contacts=) and relative timestamps (=7d=). A saved query becomes a
publishable, discoverable, forkable artifact.

One spell = one filter, and Nostr filters have no join or dereference —
"events tagged =#x=" and "the events those events point at" are two
queries, the second dependent on the first. Our two motivating feeds
both have this shape:

1. /Labels → referents:/ fetch kind 1/1111 carrying a hashtag, then pull
   the root events they refer to — the query side of
   [[file:idea-post-hoc-labeling.org][post-hoc labeling]].
2. /Publications feed:/ fetch 30040s, then the kind 0s of their authors.

So the idea: keep spell = one filter, and add *composition* as its own
small layer. Two spells and a pipe subsume any ad-hoc "deref" extension.

* The language

Three variable namespaces complete the grammar (a spell is a function
=(args, identity, input) → filter=):

#+begin_example
$me, $contacts       identity context    (NIP-A7 as written)
$arg.<name>          invocation context  (user-supplied at run time)
$in.<projection>     pipeline context    (upstream stage's result set)

projection = "ids" | "pubkeys" | "tag." letter [":" marker]
#+end_example

- =["param", <name>, <prompt>]= declares an argument (machine-readable
  signature; clients prompt for unbound params).
- A spell containing =$in.*= is /partial/ — runnable only inside a
  pipeline. Unbound variables keep NIP-A7's rule: don't send, explain.
- *Expansion rule:* variables expand in place; a filter tag's values
  concatenate and dedup. So =["ids", "$in.tag.E", "$in.tag.e:root"]=
  unions NIP-22 =E= roots with NIP-10 root-marked =e= tags — no new
  mechanism, filter tags already take multiple values.

* Composition

Two forms, one semantics. The *minimal* form is =in= chaining: a
REQ/COUNT spell carries =["in", <spell-event-id>]= and applies its own
filter to that spell's results — "previously defined: retrieve events
with tag X; current: of those events, pull the root references". No new
terminology beyond the tag mirroring the =$in= namespace; the chain is
one event.

The *general* form: a pipeline is itself a kind 777 with =["cmd",
"PIPE"]= and ordered =["stage", <spell-event-id>, <combinator>]= tags.
Combinator algebra — deliberately tiny (every combinator is something
all clients must implement or degrade around):

- =map= — replace results with their referents. *Pass-through rule:* an
  upstream event contributing no projection values is its own referent
  (a live run on =#asknostr= found 11 of 15 labeled events were
  top-level posts — dropping non-replies would discard most of the set).
- =join= — keep results, fetch auxiliary events alongside (profiles
  enrich publications; they don't replace them).
- maybe =union= (merge spells into one feed); stop there.

Stages reference spells /by event id/, which makes small generic spells
a shared library: "kind 0s of =$in.pubkeys=" or "roots of =$in=" get
written once, network-wide. Fork provenance rides the existing =e= tag.

A /closure/ binds a pipeline's params durably: a fork (=e= → parent
pipeline) with =["arg", <name>, <value>]= and no stages of its own —
"Referents of =#devstr=" as a one-tap feed.

* Worked example: labels → roots, parameterized

Spell A — finder (parameterized):
#+begin_src json
{"kind": 777, "tags": [
  ["cmd", "REQ"], ["name", "Filed under #{tag}"],
  ["param", "tag", "hashtag to collect labels for"],
  ["k", "1"], ["k", "1111"],
  ["tag", "t", "$arg.tag"], ["since", "30d"], ["limit", "100"]]}
#+end_src

Spell B — root deref (the universal library spell):
#+begin_src json
{"kind": 777, "tags": [
  ["cmd", "REQ"], ["name", "…their roots"],
  ["k", "1"], ["ids", "$in.tag.E", "$in.tag.e:root"]]}
#+end_src

Pipeline: =["cmd","PIPE"]=, =param tag= re-declared (unbound =$arg.*= in
stages escalates to the pipeline's signature), =["stage", A]=,
=["stage", B, "map"]=. Execution: resolve args → run A → expand =$in.*=
over A's results → run B → apply map pass-through, dedup by id. The
runner keeps the inverse mapping (root ← labeling events) as provenance
("filed by 3 people") — engine-derived, not wire format.

* Roadmap — the composer epoch (2026-07-09)

Four features; 1 → 2 → 3 are a dependency spine, 4 lands in parallel.

- [X] *Spell narration + query-string equivalence* (=inspect=): the
  preview quotes the spell *in our search syntax* — one clause per line
  (=k:30617= / =limit:200= / =relay:wss://…=), annotated only where a
  clause isn't literal (=by:$contacts — resolved at run time=,
  =t:$arg.tag — prompts "hashtag"=). The DSL is the human-readable
  form; =query_string= is just the clauses joined. PIPE spells unpack
  behind a =v= chevron on the card: collapsed = stage names +
  combinators, expanded = each stage spell's clause block. Web: card
  expand on the Spells tab; the composer reuses the same preview.
- [X] *Relay syntax in search* (=search.rs=): repeatable =relay:wss://…=
  token → relay override, plus =limit:N=. Makes search ↔ spell mapping
  lossless both ways (=close-on-eose= stays implicit — our fetch path is
  already one-shot REQ→EOSE→CLOSE).
- [X] *Spell composer*: =SearchQuery → Spell= compile (=to_tags()= is the
  emission half) → unsigned 777 template → existing signing flow
  (signing-is-the-snapshot; publish deliberate). Web: "Save as spell"
  from the search bar; composer pass = name/description/topics +
  *parameterization* (promote a query literal to =$arg.<name>= with a
  prompt string). =~:= semantic queries don't compile portably —
  degrade to NIP-50 =search= with a warning, or refuse.
- [X] *Spellbooks as the primary object* (supersedes bookmarks-as-
  afterthought): the profile Spells tab pulls the user's *book* — a
  NIP-51-style set (proposed *kind 30777*: addressable, =d= names the
  book so one user can keep several, =title=/=description= metadata,
  =e= tags → spell events *regardless of author*) — and resolves its
  entries with authorship visible per entry (used-not-authored
  legible). "Bookmark" = "add someone's spell to my book" from their
  profile tab. Authored-only kind-777 query is the fallback when no
  book exists; open call: book-first with an "Authored" section below
  (lean yes — curation is the signal, own spells shouldn't vanish).
  Local-first via the existing model: unpublished book = local draft;
  publishing it is the deliberate act (signing-is-the-snapshot — no
  bespoke spellbook.json). Arg re-binding on a foreign spell = closure
  fork with =e= provenance (already engine-side).

* Spellbooks

A spellbook is a NIP-51 set whose =e= tags point at 777s — /not/ a
30040 (NKBIP-01 addresses replaceable sections by =a= tag; spells are
non-replaceable, id-addressed). Opening the set lists spells; opening a
spell runs it into a feed. It recurses pleasantly: a spellbook can hold
a spell querying =k:777 #t=curation= — a feed /of spells/ discovered
from the network beside the hand-picked ones.

* tendrl mapping

- =search.rs= is already the textual DSL for the same object: =k:30040
  by:me since:7d= and a spell's tags are two serializations of one
  filter (=by:me= ↔ =$me=). Aim for a bidirectional compile: saved
  search → kind 777; any spell → editable query text in the search bar.
- =~:= semantic search has no portable equivalent — NIP-50 =search= is
  the lossy export; a =~:= spell stays local-only or degrades.
- Publishing philosophy holds: spells are local saved-searches first;
  publishing one is a deliberate act
  ([[file:feat-publishing.org][publishing]]).
- Boundary: pipeline execution (resolve vars → REQ → project → next
  stage) is event-derivation — Rust. Web renders spellbook buffer →
  feed buffer, a natural fit for the WM model
  ([[file:feat-shell.org][shell]]).
