#+TITLE: Reader
#+TYPE: feature
#+STATUS: implemented
#+DATE: 2026-07-05

The reading surface for NKBIP-01 publications. One buffer, three view modes,
fed by an engine-side tree stream so ordering, dedup, and a-tag resolution
never happen in the browser.

* What exists
- Two view modes toggled with =h= / =l=: paged (one section, prev/next
  bar) and scroll (full doc, page-scroll on =j= / =k=) —
  =web/src/lib/wm/renderers/ReaderBuffer.svelte=. The outline view was
  removed 2026-09-11 (ngit issue c15f2b65 "tool buttons take up too much
  vertical space"): the =§= toc drawer is the outline, on every shell.
- Reader chrome (2026-09-11): one strip — =§= toc · =paged | scroll= ·
  =tree= · =T= · =M=. =tree= (nested publications only) drops a row with
  the load-depth stepper, expand all / collapse (toc drawer + scroll
  view together) and the ⊞ graph. =T= drops the tools panel: *actions*
  (highlight mode, comments, highlights drawer, summary, edit, edit §,
  fetch from relays, refresh threads), *pool* (context / compose /
  provenance pills), *reading* (=ReadingControls=). =M= is the event
  menu. The publication title row (title · summary · cmt/hl chip) is
  gone — the title lives in the text, provenance in =M=, the chips in
  =T=. From ≈300 px of stacked rows on a phone to one 50 px strip.
  Mockups: the "Reader Toolbar on Mobile" design canvas (Claude Code
  artifact facbf79d…, Chosen page).
- TOC via the SSE =stream_publication_tree= (=src/publication.rs=): the
  depth-N loader ships ordered =children= parent-before-child, so nested
  30040 sub-publications resolve engine-side.
- Eager-loads all sections once the TOC arrives (continuous mode's
  IntersectionObserver still covers very long publications).
- Standalone-section reader: =reader:event:<id>= synthesizes a one-section
  publication from any event id, forced paginated.
- Short-form events by id (2026-09-11, ngit issue 7aa84e75 "render
  comments and threads like normal"): a =reader:event:<id>= whose kind
  is not a document kind (30040/30041/30023/30818/30817) no longer gets
  wrapped as a one-section publication — the section template dressed
  a kind-1 note as "Section 1" with a pager and Edit §. It renders as
  =NoteView.svelte=: the section card's column and reading face, a
  kind label (=kindLabel=, "short note" / "comment" / "kind N") where
  the section title was, author · time, the standard pool/provenance
  pills + menu, a rich body (=RichContent=), and the NIP-22 thread
  rooted at the event underneath (local store on mount, "Pull thread
  from relays" Confirm-gated, reply box). The reader toolbar hides; the
  buffer label is the kind name, not "section". Comment bodies in
  =DiscussionViewBuffer= and =CommentThread= nodes went from pre-wrap
  text to =RichContent= at the same time.
- =Edit= / =Edit §= import the publication (or the cursored section) into
  the compose pool as default-locked blocks and open the composer.
- Always pristine: a published 30040 shows the engine's view even if a draft
  was seeded from it (draft preview lives in =draft-reader:current=).
- Highlight overlays: a =?highlight=<id>= buffer suffix renders NIP-84 spans
  over content (=web/src/lib/components/RichContent.svelte=; span resolution
  engine-side in =src/discussions.rs=). A highlight is a *decoration*, not
  a replacement (2026-09-15, ngit issue "highlight removes linking
  capabilities"): =buildSegments= gives a highlight segment =parts= — the
  text runs and any nostrdown ref/token it covers — and =RichContent=
  renders the =<mark>= around them, so a =[[wikilink]]= under a highlight
  stays a live link. Refs/tokens are atoms: a highlight starting inside
  one starts after it, one ending inside one extends to its end.
- The reading place persists (2026-09-15, ngit issue "remember reading
  state of publication / reader view"): mode, section, load depth, the
  refocus breadcrumbs, the toc-drawer and scroll-view expansion sets and
  the summary / comments / tree / tools toggles are parked in
  =store.bufferState= on unmount and re-seeded on mount — leaving for the
  feed and coming back lands where you were (Emacs save-place, per
  publication; survives a killed buffer too). In scroll mode the pixel
  offset comes back as well: both scrollers report =onscroll= into a plain
  tracker (a torn-down element reads 0) and the offsets are re-applied
  once the tree settles, twice, unless the user scrolls first. Rationale in
  [[file:decision-buffer-state-homes.org][where buffer state lives]].
- Markup layers (2026-10-01, default-on + Org/AsciiDoc 2026-11-02):
  decorated-source bases over the stored text (=web/src/lib/layers/=;
  Markdown via lezer, Org and AsciiDoc via hand-written subset
  tokenizers). The toolbar chip (=md= / =adoc= / =org= / =off=) shows the
  base in force and opens the tools sheet; T → *markup* picks per buffer
  (off + enabled bases) and promotes a pick with armed "always for
  <mimetype>" / "always for this book" buttons. Decision: the section's
  =m= tag → the kind's spec (30023, 30818) → the enclosing index's → the
  user's untagged fallback → their pick — never a guess; a =?highlight=
  link forces source. =DocBuffer= decides the same way from the
  single-event endpoint's =effective_format=. Style
  spans ride =applyStyles= over =buildSegments= so the 1:1 offset mapping
  (highlights, nostrdown) is untouched. Design + checklist:
  [[file:idea-rendering-layers.org][Rendering layers]];
  [[file:decision-mimetype-tag.org][the m-tag decision]].

- Narration (2026-11-09, =feat/audiobook-blossom=): a publication's
  kind-32176 recordings ride along with the tree — discovered locally
  when the stream finishes, from relays with *fetch from relays* or the
  drawer's ⟳. Tools › *recordings N* opens =NarrationDrawer=; ▶ on a
  section title and *▶ listen* in the strip feed the global
  =NarrationPlayer=; *narrate* opens =NarrateModal= (ppq TTS → Blossom).
  Design + decisions: [[file:idea-audiobook-blossom.org][audiobooks on Blossom]].
- Reading / listening history (2026-11-09, =feat/listening-history=): the
  engine keeps one line per document in =<data_dir>/history.json=
  (=src/history.rs=, =/api/v1/history=; local, never an event). Tracked:
  publication indexes (30040) with the section last shown, and the atomic
  documents (30023 articles, 30818 wikis); a 30041 is recorded only
  *inside* its publication — opened on its own it leaves no entry. The
  player writes the listening place (section, recording, piece, position)
  every few seconds and on pause/stop; a finished book clears it. A fresh
  open of a publication jumps to the remembered section; *▶ listen*
  resumes at the remembered position on the same recording; the feed's
  *history* tab lists entries (📖 / 🎧) with *▶ listen* and *×*. The
  narration playback rate persists in the browser (=tendrl.narration.rate=)
  and survives section/piece changes (=load()= resets it otherwise).
- Attached events + the chapter player strip (2026-11-09,
  =feat/attached-events=): every chapter with audio renders a slim
  strip at the top of its body (▶ · narrator · voice · length ·
  progress · *recordings* → the drawer) — the title ▶ is gone. The
  section menu shows the *publication row* (index, publisher, published
  at) and coloured chips — comments, highlights, narration index, 30040
  index, audio — each opening the event in place; the first open per
  document asks the publication's provenance relays, ungated. A 32176
  opened on its own routes to the reader when its publication is local,
  else to the audio view. See [[file:feat-attached-events.org][Attached events]].

- Reader chrome (2026-11-12): in paged view the Prev/Next bar stays
  pinned — the page scrolls inside =PaginatedView=, not the whole
  column. The tools sheet (=T=) folds per section (actions · pool ·
  markup · reading, ▸ heads, only actions open by default, remembered
  per buffer) and is capped at =min(45vh, 420px)=. Markup gains a
  *syntax* row (rendered | show markers), and a base draws tables as an
  aligned, sideways-scrolling grid
  ([[file:decision-table-grid.org][decision]]). The highlights drawer
  follows the view: on a page it lists that page's highlights only
  (=· this page=).

* Gaps / open edges
- Nested-publication packed cards, drill-in with breadcrumbs, and parent
  navigation are Phase 3 roadmap (=docs/wm-shell.md=).
- =ReaderBuffer='s addr-keyed re-accumulation of tree events is a thin twin
  a flattened-TOC stream would drop (optional refinement).
- Performance (2026-08-12 audit): +[[file:fix-reader-effect-churn.org][effect
  churn]] (2 s full-document POST loop)+ (fixed same day:
  equality-guarded poll, stable effect keys, parse/highlight session
  caches, visible-first resolve, duplicate 5 s poll deleted),
  [[file:fix-reader-remount-cost.org][remount cost]] (switch-back
  re-streams everything — the *place* is restored since 2026-09-15, the
  re-stream remains), [[file:fix-reader-render-hotpath.org][render
  hot path]] (O(N²) deriveds, index-keyed each blocks) — and the
  structural cure, [[file:fix-resolve-in-stream.org][resolve-in-stream]].
  Fixed same day: [[file:fix-sequential-section-loads.org][sequential
  section loads]] — the tree stream's leaves now load
  bounded-concurrent with one batched relay REQ per relay for misses,
  so a partially-local publication paints local sections immediately
  instead of stalling behind serial per-section relay fanouts.
