** 1.1 Implement =\{\{@…\}\}= mentions (=RefKind::Mention=)

The spec ([[file:nostrdown-spec.md][nostrdown-spec.md]]) lists =@= mention (npub /
nprofile) as *shipped*, but the tokenizer rejects it — code and spec disagree. Add
=RefKind::Mention=: parse =\{\{@npub1…\}\}= / =\{\{@nprofile1…\}\}=, render an inline
=@handle= link (not the full profile card =embed= gives), emit the same =["p", pubkey,
relay]= tag. =@name= (mention by /name/, needing contact resolution) stays reserved —
this task is entity-only, closing the code/spec gap.

** 1.2 Rust parse endpoint; delete the TS grammar twins

Per [[file:zettel/decision-nostrdown-parsing.org][the parsing decision]] (accepted): the
grammar is data-layer, so it lives in Rust. Expose a lightweight parse surface (a parse
endpoint, or parsed token spans shipped with =resolve= responses) and delete the TS
copies — =normalizeSlug=, =isMarkupLinkTarget=, =parseWikilink=, and the token regexes
in =nostrdown.ts= / =nostrdown-cm.ts= (which already disagree about =slot=). The editor
keeps low-latency marking via engine-returned spans (debounced), not a local grammar.
This resolves what my earlier draft filed as an open question — it is decided.
