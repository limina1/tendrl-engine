#+TITLE: Publication Fetching — Status & TODO
#+DATE: [2026-05-15]

Status of NKBIP-01 publication fetching in tendrl-engine. Companion to the
full design in [[file:publication-tree-design.md]].

* Context

A publication (kind 30040) references its children — sections (30041) and
nested sub-publications (30040) — via =a= tags. Fetching one is inherently
recursive and lazy: you start from a root index and resolve children outward,
one level at a time.

* DONE Recursive depth-N publication tree loader
CLOSED: [2026-05-15]

=PublicationEngine::load_publication_tree(addr, max_depth, policy)= in
=src/publication.rs=. Merged to =tendrl-web= (merge commit 6b32485, loader
commit ebc82ff).

- Resolves a root 30040, loads its 30041 sections, then recurses into nested
  30040 indexes down to =max_depth= (0 = this index + its own sections only;
  N = recurse N levels of nesting). Sections are leaves, never a level.
- Sibling nested indexes are fetched concurrently, bounded by
  =buffer_unordered(8)=. Depth is sequential per branch; breadth is parallel.
- Cycle-safe: an =a= tag pointing back at an ancestor (or itself) is not
  recursed into — its stub is left =Pending=. Verified with an A→B→A fixture
  loaded at depth 100.
- Failure-isolating: a nested index that fails to load becomes
  =LoadStatus::Failed= without aborting its siblings.
- Unit tests: =test_load_publication_tree_depth=,
  =test_load_publication_tree_cycle_safe=.

* TODO Test & verify the loader against real publications
:PROPERTIES:

The current tests use *synthetic, locally-ingested fixtures* with
=FetchPolicy::LocalOnly=. The loader has *not* been exercised against the
network or against real-world publications. Before relying on it:

- [ ] Verify against a real multi-level publication fetched from relays
      (=FetchPolicy::LocalFirst= / =FetchAlways=) — confirm nested 30040s
      resolve and section content loads end to end.
- [ ] Verify the missing-event path: an =a= tag no relay can satisfy should
      yield =LoadStatus::Failed= and must not hang the load.
- [ ] Confirm =get_addressable= relay backfill interacts correctly with the
      concurrent breadth fetch (subscription churn, dedup, EOSE handling).
- [ ] Measure a deep =max_depth= on a large publication — event count,
      latency, memory — and pick a sane default depth.
- [ ] Cross-author publications: nested 30040s owned by a different pubkey
      than the root.
- [ ] Decide whether the depth-N load should be gated by a confirm step
      (design §9.4) before it commits to fetching.

* DONE Wire the loader into the API and web UI
CLOSED: [2026-05-16]

The recursive loader is now reachable from the reader. Opening a publication
loads it at a default depth of 2, displays the depth-N tree indented by
nesting level, and lets the reader walk into nested indexes and back out via
breadcrumbs — DB-first, with relay backfill on a miss.

- [X] API endpoint to open a publication at a given depth (design §10).
      =GET /api/v1/publications/:pubkey/:d_tag?depth=N= now calls
      =load_publication_tree= instead of the single-level =load_publication=.
      =depth= defaults to 2 and is clamped to 12. The response =toc= is the
      recursive =TocEntry= tree built by =build_toc=.
- [X] =TocEntry= carries =content= (the section body, for resolved 30041
      leaves inside the depth horizon) and =is_publication= (30040 vs 30041).
      A depth-N load fully loads in-horizon sections, so the whole indented
      tree — content included — arrives in one call; no per-section round
      trips until you refocus past the horizon.
- [X] Web: =depth= stepper in the reader toolbar; the recursive TOC is
      flattened depth-first into the section list, each entry tagged with its
      nesting =depth=. All three views (Outline / Paginated / Continuous)
      indent by depth and render a nested 30040 as a refocus affordance.
- [X] Refocus-on-click into a nested 30040 (design §9.3): pushes the current
      focus onto a breadcrumb stack, re-roots the reader on the sub-publication,
      and loads it at the same depth — fetching whatever events had not yet
      been resolved for that level. A breadcrumb bar above the views walks
      back up; clicking a crumb pops the stack to that level.
- [X] =build_toc= "load more" at the depth horizon: a nested index left
      =Pending= at the horizon now renders as the same refocus row as any
      other 30040 — clicking it triggers the deeper load. Refocus *is* the
      "load more" affordance.

Implementation: =get_publication_handler= (=src/api.rs=), =TocEntry= +
